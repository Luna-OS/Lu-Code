# luCode 1.1.2

Die Anmeldung mit Google (Gemini) klappt unter Windows, und „Aktualisieren“ kann luCode nicht mehr beschädigen.

## Behoben

- **Anmeldung mit Google (Gemini)** – In der App öffnet die Gemini-CLI die Google-Anmeldung jetzt selbst im Browser und bekommt die Antwort direkt zurück: kein Link aus dem Terminal, kein Code zum Abtippen. Bisher musste der rund 700 Zeichen lange Anmelde-Link erst durchs Terminal und kam unter Windows auch mit 1.1.1 noch abgeschnitten im Browser an („Required parameter is missing: response_type“). Auf einem Server (Docker), wo der Browser auf einem anderen Rechner läuft, bleibt es bei Link und Code.
- **„Nicht unterstützte 16-Bit-Anwendung“ nach dem Update** – „Aktualisieren“ lud bei GitHub statt des Programms nur dessen Beschreibung (JSON) und setzte sie als `luCode.exe` ein. Danach startete luCode nicht mehr und musste neu installiert werden. Jetzt lädt die App die richtige Datei, setzt nur ein, was zur Prüfsumme des Releases passt, prüft vor dem Tausch, dass es ein vollständiges Windows-Programm ist, und holt die bisherige Version zurück, falls die neue nicht startet.

## Geändert

- Unter Windows kommen Updates aus der ZIP (`luCode-1.1.2-x64.zip`, halb so gross wie das Programm). Eine einzelne `luCode-…-x64.exe` liegt nicht mehr bei.

## Installieren (Windows x64)

**Von 1.1.1, 1.1.0 oder 1.0.0: bitte einmal von Hand aktualisieren.** **luCode-1.1.2-Setup.exe** ausführen – Daten, Konten und Chats bleiben. Wer die ZIP nutzt: entpacken und `luCode.exe` ersetzen. Der Updater dieser Versionen hat den Fehler oben. Damit er luCode nicht beschädigt, findet er in diesem Release keine Datei für sich und meldet das nur. Ab 1.1.2 aktualisiert sich die App wieder selbst.

**Neu:** **luCode-1.1.2-Setup.exe** ausführen (Installer je Benutzer, ohne Administratorrechte) – oder **luCode-1.1.2-x64.zip** entpacken und `luCode.exe` starten. Windows SmartScreen fragt beim ersten Start evtl. nach (die App ist nicht signiert): *Weitere Informationen* → *Trotzdem ausführen*.

---

**English:** Signing in with Google for Gemini works on Windows: in the app the Gemini CLI now opens Google's sign-in in your browser itself and receives the answer directly – no link from the terminal, no code to type. Until now the long sign-in link had to pass through the terminal and still arrived cut off on Windows with 1.1.1. On a server (Docker) it stays link and code. **"Unsupported 16-bit application" after updating:** *Update* downloaded GitHub's description of the file (JSON) instead of the program and installed it as `luCode.exe`. The app now downloads the right file, installs only what matches the release's checksum, checks that it is a complete Windows program before swapping, and puts the previous version back if the new one does not start. Windows updates now come from the ZIP; there is no single `luCode-…-x64.exe` any more. **Coming from 1.1.1, 1.1.0 or 1.0.0, please update once by hand:** run **luCode-1.1.2-Setup.exe** (your data stays) – the updater of those versions has the bug above, so this release offers it no file instead of letting it break luCode. From 1.1.2 on the app updates itself again.
